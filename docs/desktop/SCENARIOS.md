# Desktop app for Windows and Linux — scenarios

The Windows and Linux app (`desktop/`, Tauri 2, docs/design/WINDOWS-LINUX.md W8) does what the macOS app
does: the same persona P-01, the same jobs, the same engine protocol (`observatory-assistant/1`). Its
scenarios are the macOS ones, [SCN-001–011 and SCN-014](../macos/SCENARIOS.md), plus SCN-012 and SCN-013 below; this page records only what differs on
these systems and which module delivers each. A scenario is "shipped" here only when a test or a recorded
walkthrough on that system covers it.

| ID | Difference on Windows and Linux | Module | Status |
|---|---|---|---|
| SCN-001 | The engine is looked for where README → Install puts it: Windows `%LOCALAPPDATA%\project-observatory-venv\Scripts\project-observatory.exe`, then `~\.local\bin\project-observatory.exe`; Linux `~/.local/share/project-observatory-venv/bin/project-observatory`, then `~/.local/bin/project-observatory`. The workspace defaults to `%LOCALAPPDATA%\project-observatory-full` (Windows) or `~/.local/share/project-observatory-full`. No engine: «Observatory is not installed yet» with the path, Settings and the installation guide | W8a | draft |
| SCN-002–004, 006 | The assistant window opens with Ctrl+Shift+A or View → Assistant instead of ⇧⌘A: conversations, a question at a time (one request id per draft), answers rendered as text with their evidence and next steps, Stop cancels the job, each engine refusal named with its next step | W8b | draft |
| SCN-005 | Settings (menu → Settings, Ctrl+,): program and workspace with the system's file picker, Save and check connection; a change reloads the dashboard for the new workspace and drops late answers of the old one | W8a | draft |
| SCN-007 | Opening the app shows the dashboard in its own window: the live server for THIS workspace, else the saved pages | W8a | draft |
| SCN-008 | Saved pages carry a banner with their build time and **Start server** (an installed always-on server restarts through its Task Scheduler task or systemd unit; otherwise the detached `full open --serve` start); no pages → **Build the dashboard**; a port held by another workspace is named and Start is disabled | W8a | draft |
| SCN-009 | Closing the window keeps the app in the notification area (tray) and the app keeps working (`desktop/src-tauri/src/main.rs`, `CloseRequested` → `prevent_close` + hide); the tray's Open, a second launch, or the taskbar brings the window back; the app quits only through Quit in the tray or the File menu (Ctrl+Q) or a process shutdown | W8a | draft |
| SCN-010 | Updates come through the app's own updater (a minisign-signed package named by the release's `latest.json`, a static release asset, never the GitHub REST API; fabric-workspace platforms.md PL-04), on by default: the first check 90 seconds after start, then every five minutes, a failed check retried after five minutes; a check that finds nothing new is logged once, not every time. A found update is downloaded and verified in the background, then the person is asked once per version **Restart to finish updating** (Restart now / Later); Later keeps **Restart to update** in the menu and the tray, which installs the downloaded package and restarts. The version asked about is kept in the app's config folder (`update-prompted-version`), so a restart does not ask again. A package that fails to download is fetched again after 5 minutes, then 10, 20, … at most six hours apart (a newer version starts over); the feed is still read every five minutes. An install that fails is said in a message with its reason, and the downloaded package stays kept so **Restart to update** tries again. A `.deb` copy and a debug build never check (`updates.rs` tests `checks_run_every_five_minutes_and_the_first_shortly_after_start`, `the_feed_is_the_static_release_asset_never_the_rest_api`, `a_check_that_finds_nothing_new_is_logged_once`, `the_restart_prompt_is_asked_once_per_version_across_restarts`, `a_failing_package_backs_off_to_six_hours_and_a_new_version_starts_over`, `a_failed_install_is_said_with_its_retry`; the dialog itself: no automated test) | W8c | draft |
| SCN-011 | The interface follows the system language (Russian for `ru`/`ru-*`, else English); Settings → Language overrides it; the dashboard's own `observatory.locale` follows | W8a | draft |
| SCN-012 | The app opens at login by default, in the tray with no window (`--background`): the first launch writes the login entry and keeps the choice on; Settings → **Open at login** turns it off (the entry is removed at once) or on again, and an update keeps the choice. Windows: the value «Project Observatory» under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; Linux: `$XDG_CONFIG_HOME/autostart/ai.passioncode.observatory.desktop`. A debug build never writes one (`autostart.rs` tests `a_first_launch_turns_it_on_and_a_kept_choice_is_respected`, `the_desktop_entry_starts_the_program_in_the_tray`, `exec_quoting_follows_the_desktop_entry_spec`, `the_run_value_quotes_the_program_and_starts_it_in_the_tray`; `settings.rs` `a_settings_file_from_before_launch_at_login_still_loads_and_the_choice_survives`; the Settings checkbox and the login start: no automated test) | W8a | draft |
| SCN-013 | Every launch checks what the app needs from the system. The app needs no OS permission on Windows or Linux; what can be missing is the login entry the person asked for. An entry that could not be written is named in a message with the error and how to fix it (allow the write, or turn **Open at login** off in Settings); an entry that is gone, or switched off by the desktop (`Hidden=true`, `X-GNOME-Autostart-enabled=false`) or in Windows' Startup apps (the `StartupApproved` value), while the choice is on is never rewritten silently: it is named with where it lived and offers **Restore** or **Turn off**. Never silent (`autostart.rs` tests `an_entry_gone_while_the_choice_is_on_is_never_silent`, `an_entry_the_desktop_switched_off_is_not_rewritten`, `a_startup_app_switched_off_in_windows_settings_is_read`, `a_copy_that_manages_no_entry_does_nothing`; the messages themselves: no automated test) | W8a | draft |
| SCN-014 | Pairing this machine (portable scenario OSS-94, OBS-197): File → **Pair this machine…** opens the `ceremony` window, which draws the engine's screen (`full assistant ceremony`) and reads it again every five seconds; it sends only the ceremony's steps (`main.rs` `ceremony_input`, test `the_pairing_window_sends_only_the_ceremonys_steps`) and its words have their Russian (`tests/test_desktop_app.py`); the window itself: no automated test | W8a | draft |

Navigation stays inside this workspace's pages, as on macOS: other sites and `mailto:` open in the default
browser or mail app, and any other scheme is refused, so a page cannot launch a program.
